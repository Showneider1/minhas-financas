# Skill: product-discovery

## Objective
Identify user needs, pain points, and opportunities to define a valuable product feature set for Finance OS.

## Context
Used at the start of any new module or feature implementation to ensure we are building the right thing for the user.

## Prerequisites
- Understanding of the current target persona.
- Access to user feedback or market research.

## Execution Procedure
1. **User Research**: Identify the core problem the user is trying to solve (e.g., "I don't know where my money goes").
2. **Job-to-be-Done (JTBD)**: Define the "job" the user is hiring the feature for.
3. **Hypothesis Generation**: Formulate a hypothesis: "If we build [X], then [Y] will happen, resulting in [Z] value."
4. **Validation**: Validate hypotheses through user interviews, surveys, or rapid prototyping.
5. **Definition**: Translate validated needs into User Stories and Acceptance Criteria.

## Technical Patterns
- User Story Mapping.
- Lean Canvas.
- Event Storming for business processes.

## Examples
- Discovery for "Investment Tracking": Users want to see "Realized vs Unrealized" gains without calculating them manually in Excel.

## Validation Criteria
- Clear User Stories with "As a [role], I want to [action], so that [value]".
- Validated pain points backed by evidence.
- Acceptance criteria that are binary (yes/no).

## Common Errors
- Building features based on assumptions without validation.
- Over-complicating the feature before understanding the core need.

## Security Rules
- Do not use real user PII during the discovery/prototyping phase.

## Deliverables
- Discovery Report.
- Validated User Stories.
- Initial Feature Map.
